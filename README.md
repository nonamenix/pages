# pages.live4.dev

Минималистичная публичная площадка для статей. Strapi 5 хранит черновики и медиа, Astro генерирует статические страницы, а отдельный publisher проверяет и атомарно переключает релизы.

## Архитектура

- `backend/` — Strapi 5.52.0, Draft & Publish, Blocks и закрытый publisher API;
- `src/` — Astro 6.4.8, главная и страницы `/<slug>/`;
- `publisher/` — сериализованная сборка, 15-минутные подписанные preview, release validation и rollback;
- `caddy/`, `scripts/`, `systemd/` — production routing, публикация и проверяемые backup;
- production state — PostgreSQL `pages_live4dev`, отдельные uploads и `/srv/pages-live4dev/current`.

Content API статей доступен по HTTPS через `/api/articles` и `/api/articles/<documentId>` с заголовком `Authorization: Bearer <token>`. Caddy требует Bearer-заголовок, а Strapi проверяет API token и его права на статьи. Без Bearer-заголовка API возвращает `401`; анонимные права Strapi выключены. Остальные `/api/*`, включая внутренний publisher API, возвращают `404`. Админка доступна по `/admin` только после входа. MCP в этом проекте не включён.

На индексируемых публичных страницах подключена Яндекс Метрика `111762995`. Инициализация вынесена в локальный `public/metrika.js`, чтобы сохранить строгий CSP без `unsafe-inline`; подписанные preview и страница 404 не отправляют данные в Метрику.

## Редактор Pages

Войдите в существующий аккаунт администратора Strapi через `/admin/auth/login`. Новая статья создаётся на `/new`; кнопку «Редактировать» у опубликованной статьи можно нажать прямо на её странице. Доступ определяется правами Content Manager на чтение, создание, изменение и публикацию статей.

Редактор использует Strapi Blocks: абзацы, заголовки, выделение, ссылки, цитаты, списки и изображения с обязательным описанием. Выделите текст, чтобы открыть панель форматирования; кнопка `+` у пустого абзаца добавляет изображение. Заголовок и автор редактируются на странице. При создании адрес, описание для поиска, язык и дата заполняются автоматически; при изменении сохраняются существующие метаданные и обложка.

«Сохранить черновик» оставляет публичную версию без изменений. «Опубликовать» сохраняет и публикует документ в CMS, затем ждёт появления именно этой версии в проверенном статическом релизе. При ошибке, истечении сессии или конфликте изменения остаются в редакторе. На `/new?draft=<documentId>` можно снова открыть сохранённый черновик. Закрытие вкладки с несохранёнными изменениями вызывает предупреждение браузера.

Главная, статья, редактор, 404 и страница установки используют визуальную систему `live4.dev`: локальный Golos Text, светло-зелёный фон, тёмно-зелёную палитру, тонкие разделители и общий фирменный знак. На главной публикации собраны в спокойный адаптивный список с описаниями, автором и датой; статья сохраняет узкую меру строки для чтения. Источник и лицензия шрифта указаны в `public/fonts/SOURCE.md`.

Сессия используется через небольшой same-origin iframe `/admin/pages-session.html`, собранный вместе с админкой. Официальный fetch client Strapi читает существующий admin cookie по пути `/admin` или сохранённую сессию и обновляет её штатным способом. Родительская страница получает только результат разрешённых операций, без передачи токена. Другие страницы админки сохраняют запрет на встраивание. Анонимные права Content API не изменяются.

На `/new` Метрика не подключается. При редактировании опубликованной статьи содержимое редактора помечено классами `ym-hide-content` и `ym-disable-keys`, [исключающими его запись Вебвизором](https://yandex.ru/support/metrica/ru/webvisor/settings).

## Скилл Pages для Codex

Публичная страница установки скилла: `/pages-site.html`. Поддерживаемый исходник находится в `skills/pages-site/`; `python3 scripts/package-skill.py` создаёт воспроизводимый ZIP, контрольную сумму, манифест и установщик в `public/`. После изменения скилла обновите версию в скрипте и пересоберите пакет. Установщик проверяет SHA-256, поддерживает `CODEX_HOME` и сохраняет существующую установку. Для проверки пакета и установки выполните `python3 tests/test_skill_distribution.py`.

## Локальная разработка

```sh
cp .env.example .env
docker compose up --build
```

- Strapi: `http://127.0.0.1:4351/admin`;
- publisher health: `http://127.0.0.1:4352/health`;
- статический релиз: `.releases/current`.

Frontend без Strapi:

```sh
npm install
npm run dev
npm run build:empty
npm run build:fixture
```

## Публикация

1. Создать статью в Strapi, заполнить title, slug, excerpt, publishedOn, language и Blocks body.
2. Для всех inline-изображений заполнить alternative text.
3. Сохранить draft. Он не попадает в публичный sitemap или текущий релиз.
4. Получить подписанный preview: `sudo -n /opt/pages-live4dev/scripts/preview.sh /<slug>/`.
5. Нажать Publish. Publisher собирает весь сайт и меняет `current` только после полной проверки.
6. Unpublish запускает новую сборку и удаляет маршрут из публичного релиза.

Slug должен состоять из `a-z`, цифр и дефисов. Зарезервированы `admin`, `api`, `uploads`, `__preview`, `_health`, `mcp`, `new` и `fonts`.

Для работы через HTTP используйте стандартный Strapi 5 REST API: `GET`/`POST /api/articles`, `GET`/`PUT`/`DELETE /api/articles/<documentId>`, JSON с объектом `data`. Обязательные поля: `title`, `slug`, `excerpt`, `publishedOn` (дата), `language` (`ru` или `en`) и `body` (Strapi Blocks). При записи явно указывайте `status=draft` или `status=published`; публикация запускает существующий publisher. Токен для Content API создаётся в Strapi с необходимыми правами на статьи; `STRAPI_API_TOKEN` из серверного окружения используется внутренним publisher и не является таким токеном.

## Проверки

```sh
npm run test
npm run build:empty
npm run build:fixture
npm --prefix backend run typecheck
npm --prefix backend run build
docker compose config
```

Полная браузерная проверка создаёт отдельную локальную базу SQLite, временного администратора и тестовые статьи. Она проверяет вход с cookie `/admin`, черновик, изображение, публикацию, редактирование на странице, конфликт изменений, истечение сессии и мобильную вёрстку. Production-доступ не нужен:

```sh
npm run test:e2e
```

Если запуск Chromium ограничен на macOS, используйте изолированный контейнер:

```sh
docker build -f tests/Dockerfile.editor -t pages-live4dev-editor-test .
docker run --rm --init pages-live4dev-editor-test
```

Production-процесс, approval gates и rollback описаны в [docs/deployment.md](docs/deployment.md).
